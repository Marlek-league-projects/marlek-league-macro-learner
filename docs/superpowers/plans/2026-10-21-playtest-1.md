# Playtest 1 Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the first playtest feedback:
- lane contacts get Farm / Trade / All-in / Flee;
- the jungle reaches lanes and objectives faster;
- sacrificing a wave for an objective is recognized;
- the screen gets a round banner, a bigger map, wave markers, objective and camp timers on the map, and an animated round replay.

**Architecture:** Same modules and contracts as the vs-AI MVP (`web → engine → data`, types in `src/contracts`, `main.tsx` is the only composition root). Rules change in `engine` and `data`. Display changes stay in `web`.

**Tech Stack:** Bun 1.4.3, TypeScript strict, Preact + @preact/signals + SVG, `bun:test`.

**Spec:** `README.md`. Read the sections "Fights → Lane contacts", "Movement" (ganks from outer camps, neutral objectives, sacrificing a wave) and "Game screen" (round banner, timers, waves, round replay).

## Global Constraints

- Every task runs `bun run typecheck && bun run check-deps && bun test && bun run build` before committing. All four must pass.
- Game values (thresholds, margins, texts) live in `packages/data/data/*.json`, never as engine literals.
- `packages/web` components import only `@lml/*/contracts` and the store. The UI shows only what `PlayerView` and `eventsFor` expose, so the fog of war holds.
- The engine stays deterministic, and randomness only goes through `Rng`.
- UI text is in French.
- The idle benchmark (`packages/engine/test/benchmark.test.ts`) must still pass: Gold and above win at least 15 of 20, and Challenger wins 20 of 20. If a rule change breaks it, re-tune data values only, and record every old → new value in the report.

## Review Focus

- A lane contact where both sides keep Farm must kill nobody and must not emit a `fight` event *(Task 2)*.
- Teaching never reveals unseen enemy moves when it explains a wave sacrifice *(Task 3)*.
- The replay must never animate an enemy that `eventsFor` filtered out *(Task 5)*.
- A countdown on an objective must never show an enemy capture or kill the player did not see *(Task 4)*.
- The larger click targets must not let a click on an unreachable position give an order *(Task 4)*.

### Task 2: Lane contacts — Farm / Trade / All-in / Flee

**Files:**
- Modify: `packages/engine/src/contracts/contacts.ts` (`Choice` gains `'farm'`), `packages/engine/src/contacts.ts`, `packages/engine/src/round.ts`, `packages/engine/src/ai/heuristics.ts`, `packages/data/data/ai-tuning.json` and its contract type and validator, plus the web labels in `packages/web/src/components/ContactPrompt.tsx` (or wherever choices are labelled).
- Test: `packages/engine/test/contacts.test.ts`, `packages/engine/test/round.test.ts`, `packages/engine/test/ai.test.ts`

**Interfaces:**
- `type Choice = 'farm' | 'trade' | 'fight' | 'flee'`. The UI labels `'fight'` as "All-in" on lane contacts and "Combattre" elsewhere.
- Trade-kind contacts have options `['farm','trade','fight','flee']` for both sides, with default `'farm'`.
- `aiTuning` replaces `killMargin` with `allInMargin` (start at 4) and `tradeMargin` (start at 0.5).

- [ ] **Step 1: Write the failing tests.**
  - On an even lane contact, farm vs farm gives no `fight` and no `trade` event and kills nobody, and the lane falls back to the fight-score push (existing I5 rule).
  - Farm vs trade gives a `trade` event with the winner from the fight score, and nobody dies.
  - Trade vs trade behaves as before.
  - Fight vs farm or trade gives a `fight` event, and the losers die.
  - A flee concedes the trade (existing rule).
  - AI choice: it picks `'fight'` only when the margin is above `allInMargin`, `'trade'` when the margin is above `tradeMargin`, `'flee'` when the margin is below `-allInMargin`, and `'farm'` otherwise.
- [ ] **Step 2: Run** `bun test packages/engine`. Expected: FAIL.
- [ ] **Step 3: Implement.** Resolution order on a trade-kind contact:
  1. A `flee` on either side is handled as today.
  2. Otherwise, any `fight` turns it into a fight.
  3. Otherwise, any `trade` turns it into a trade.
  4. Otherwise (farm vs farm) the contact has no effect.

  Update the web labels and defaults so the four buttons show with Farm preselected.
- [ ] **Step 4: Run all checks.** Re-tune data if the benchmark fails.
- [ ] **Step 5: Commit** `feat: lane contacts offer farm, trade, all-in or flee`.

### Task 3: Sacrificing a wave for an objective

**Files:**
- Modify: `packages/data/data/teaching.json` (new rule `wave-sacrifice-for-objective`, `roundsLost` 0), `packages/engine/src/teaching.ts`, `packages/engine/src/ai/heuristics.ts`, and `packages/data/data/ai-tuning.json` with its type and validator.
- Test: `packages/engine/test/teaching.test.ts`, `packages/engine/test/ai.test.ts`

- [ ] **Step 1: Write the failing tests.**
  - **Teaching, justified sacrifice:** a laner leaves its lane with the wave ≤ 0 for its side, toward a pit or scuttle whose objective was up or taken that round. This yields `wave-sacrifice-for-objective` and not `left-lane-without-priority`. The French text names the champion and the objective, for example "{champion} a sacrifié sa vague pour jouer {objective} : bon échange si ça donne le surnombre."
  - **Teaching, unjustified roam:** the same move to a non-objective position still yields `left-lane-without-priority`.
  - **Fog:** the rule only uses `eventsFor`-filtered events.
  - **AI, high rank:** a Challenger mid with `waves.mid = -1` and the Dragon spawning next round rotates toward `dragon-pit` when this gives its side more champions than the enemies it knows of near the pit. With no objective up, it stays (the `rotateWithoutPriority` mistake still covers roaming with no reason).
- [ ] **Step 2: Run.** Expected: FAIL.
- [ ] **Step 3: Implement.** The AI rule compares the objective's `value` with a data value `waveSacrificeCost` (ai-tuning). It only applies when the rotation gives a numbers advantage computed from the view.
- [ ] **Step 4: Run all checks.** Re-tune data if the benchmark fails.
- [ ] **Step 5: Commit** `feat: wave sacrifice for an objective in teaching and AI`.

### Task 5: Animated round replay

**Files:**
- Create: `packages/web/src/replay.ts` (a pure timeline builder) and `packages/web/src/components/ReplayLayer.tsx`
- Modify: `packages/web/src/components/MapView.tsx`, `packages/web/src/store.ts` (keep the pre-round view positions for the replay), `RoundPanel.tsx` (Rejouer / Passer buttons)
- Test: `packages/web/test/replay.test.ts`

**Interfaces:**
- `buildReplay(before: PlayerView, after: PlayerView, events: GameEvent[]): ReplayStep[]`. The events are `eventsFor`-filtered.
- A step is one of:
  - `{ kind: 'move'; champion; from; to }` for allies, and for enemies that are visible before or after the move;
  - `{ kind: 'fight' | 'death' | 'objective' | 'camp' | 'tower'; position; label }`.

- [ ] **Step 1: Write the failing tests.**
  - The ally moves from the round's events become move steps.
  - An enemy `moved` event absent from the filtered events never appears.
  - A fight produces a fight step at its position before the death steps.
  - A recall produces no slide step.
- [ ] **Step 2: Implement.**
  - When the review screen opens, play the steps on the map in about 2 s. Tokens slide (CSS transition or requestAnimationFrame), fights flash, a dead token fades out, and taken objectives and towers pop a label.
  - The "Rejouer" button restarts the replay and "Passer" jumps to the end state.
  - With `prefers-reduced-motion`, skip straight to the end state.
- [ ] **Step 3: Verify in the browser.** Play a few rounds in headless Chrome and screenshot mid-replay. Run all checks.
- [ ] **Step 4: Commit** `feat(web): animated round replay`.
