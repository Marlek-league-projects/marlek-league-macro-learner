### Task 1 (engine + data): Farm safe, health, gold on death, camp XP

- [ ] **Farm safe.**
  - On a `trade`-kind lane contact, a side whose stance is `farm` cannot die.
  - If the other side is `allin` (fight) and wins, it becomes a trade won by the all-in side: wave and `tradeLead`, plus HP loss (below). Nobody dies.
  - A fight with deaths happens only when both sides' choices are `trade` or `fight` and at least one is `fight`.
  - Tests: farm vs allin (allin stronger) means no death and an allin trade win; trade vs allin keeps the existing behaviour.
- [ ] **Health.**
  - `ChampionState.hp: number` (0–100, starts at 100).
  - Data in `rules.health`: `max` 100, `tradeLoss` 20, `tradeWinnerLoss` 5, `regenPerRound` 8, `fightWeight` 0.5.
  - A trade loser loses `tradeLoss`, the winner loses `tradeWinnerLoss`. A farm-vs-allin trade counts the same way.
  - Every alive champion regains `regenPerRound` at the end of a round. Values are clamped to 0..max. A recall completion and a respawn set it to max.
  - In `fightScore`, each champion's contributions are scaled by `1 - fightWeight * (1 - hp/max)`.
  - HP never kills by itself.
  - `PlayerView`:
    - allies expose `hp`;
    - `EnemyInfo` gets `hp: number | null`, visible only (null when not visible);
    - the estimate treats unseen enemies as full HP.
  - The AI uses its own HP: a laner under 40 HP prefers recall when its wave allows it (a tuning value in `ai-tuning.json`).
  - Tests: clamping, restoration, the scaling effect, fog of `EnemyInfo.hp`, and the AI recall at low HP.
- [ ] **Gold on death.** `applyKill` converts each victim's unspent gold into items (`items += gold; gold = 0`) before marking it dead. Test.
- [ ] **Camp XP.** `rules.camps.buffXp` goes 100 → 230 and `smallXp` 70 → 170, so a full clear of 2 buffs and 4 small camps gives 1140 XP, which is level 4. Test: a jungler who clears all 6 own camps, counting the start buff from `newGame`, is level ≥ 4.
- [ ] Run all checks. Re-tune data only if the benchmark fails. Commit.

### Task 2 (web): draggable actions panel, champion HUD

Built in parallel with Task 1, in a worktree. Code against these contracts, and add them as types only if they are missing: `ChampionState.hp: number`, `EnemyInfo.hp: number | null`.

- [ ] **Draggable actions panel.**
  - The popover gets a title bar that works as a drag handle (pointer events), clamped inside the map box and the viewport.
  - The store keeps the dragged offset for the session.
  - On open, the initial side is the one that covers the fewest reachable positions of the selected pawn (pure helper with tests).
  - While the panel is being dragged, map clicks are ignored.
- [ ] **HUD above tokens.** For every visible pawn, stacked above the role icon in a compact layout:
  - an HP bar (green → red);
  - the power score (the existing strength value, shown as a number);
  - "niv N";
  - a thin XP bar showing progress to the next level (`engine.level` and `rules.economy.levelXp`).

  An enemy that is not visible shows nothing. The map must stay readable at 1440×1000: check overlaps on stacked bot-lane pawns, and offset when needed.
- [ ] **Team cards.** The same HP bar, power, level and XP bar on each card in both side columns. Own cards add "Or en poche N". Enemy cards show HP, level and power only while the enemy is visible, otherwise "—".
- [ ] Tests for the pure helpers (HUD values, XP progress, popover side choice and clamping).
- [ ] Take headless screenshots at 1440×1000 (not on port 3000) and Read them. Run all checks, then commit.
